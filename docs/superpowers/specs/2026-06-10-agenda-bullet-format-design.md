# Agenda Bullet Format Guide

**Date:** 2026-06-10
**Status:** Approved
**Scope:** Sync Meeting AI prompt — per-org and internal agendas (master Touch Base excluded; subject to a separate future session)

---

## 1. Problem

The AI-generated `bodyHtml` for each agenda topic currently produces bullet points with a `**Owner Name**: related info` pattern — bold name followed by a colon. This format is noisy and feels wrong in a meeting agenda context. The desired style is a cleaner em-dash separator with metadata trailing the bullet text.

---

## 2. Desired Format

```
item text — Person, Status (M/D)
```

### Rules

- **Person** — include the owner's name when ownership is non-obvious. **Exception: topics in the `content-social` category — omit the person name entirely.** (Andy owns all content work; his name is always redundant there.)
- **Status** — include only when it meaningfully qualifies the item. Accepted values: canonical status words ("In Review", "Blocked", "Done") **and** content workflow-phase qualifiers ("outline", "draft", "published", and other reasonable phases). Not every bullet needs a status. These are display labels for the agenda — they are intentionally different from board `toStatus` values ("Review", "Pending").
- **Date** — include only when a specific date was **explicitly discussed** in the meeting. Short `M/D` format, in parens, always last.
- **Person and Status** may appear together or independently.
- **Omit the `—` entirely** when there is no metadata.

### Examples

```
• Google Business Profile audit complete
• Provider directory redesign — Hugo (6/15)
• Homepage hero — Cedric, In Review
• Q3 blog post — outline
```

The four examples cover: bare bullet, person + date, person + status, and the `content-social` exception (workflow-phase qualifier, no person name).

---

## 3. Scope

This format guide applies to all `bodyHtml` bullet content generated by:

- `api/ai/prepare.js` — Sync Meeting (per-org and internal agendas)
- `api/ai/refine.js` — Sync Meeting refinement pass

It does **not** apply to the master Touch Base agenda (`master: true` path) — that agenda's structure is expected to change significantly in a future session and will get its own format design then.

---

## 4. Implementation

### Prompt text

```
## Bullet format within topic bodies
Write each bullet as:  item text — Person, Status (M/D)
Rules:
- Person: include the owner's name when it is non-obvious. Exception: content-social category topics — omit the person name entirely.
- Status: include only when it meaningfully qualifies the item (e.g., "In Review", "Blocked", "Done", or content workflow phases like "outline", "draft", "published"). The content workflow phases list is non-exhaustive — other reasonable phases (e.g. "scheduled", "awaiting approval") are also acceptable.
- Date: include only when a specific date was explicitly discussed. Short M/D format in parens, always last.
- Person and Status may appear together or alone.
- Omit the — entirely when there is no metadata.
- Note: "In Review" and "Blocked" are display labels for the agenda — they are not the same as board status values ("Review", "Pending") and the difference is intentional.

Examples:
• Google Business Profile audit complete
• Provider directory redesign — Hugo (6/15)
• Homepage hero — Cedric, In Review
• Q3 blog post — outline
```

### `api/ai/prepare.js` — `buildSystem()`

Introduce a `bulletFormatBlock` local variable at the top of `buildSystem()`. The variable includes its own leading `\n\n` so the insertion never collapses against adjacent text:

```js
const bulletFormatBlock = !master ? `\n\n## Bullet format within topic bodies\n...` : "";
```

Interpolate `${bulletFormatBlock}` in the returned template literal immediately after the TOPIC IDENTITY paragraph (the sentence ending `"...You may reorder topics and you may omit a topic whose work is fully complete."`) and before the `\n## Board changes output (boardChanges)\n` line. The result in the template literal reads:

```
...you may omit a topic whose work is fully complete.${bulletFormatBlock}

## Board changes output (boardChanges)
```

### `api/ai/refine.js` — `buildSystem()`

Same pattern: introduce a `bulletFormatBlock` variable (`!master ? \`...\` : ""`).

In the returned template literal, interpolate `${bulletFormatBlock}` after the `HTML rules:` line and before the `${master ? ...}` master conditional interpolation — both are adjacent lines inside the same backtick string. The variable includes its own leading `\n\n`.

The topic `categories` array is already present in the user message for each topic (lines 88–89 of `buildUserMessage`), so the model has the `content-social` context it needs to apply the person-name exception on refined topics.

After deploying, run Sync Meeting on a per-org agenda (e.g., a client meeting or the Vistamar Platform Development meeting) and confirm:

- No `**Name**:` bold-colon pattern appears
- Content topic bullets omit owner name
- Dates only appear when they were explicitly discussed
- Bare bullets (no metadata) have no trailing `—`
